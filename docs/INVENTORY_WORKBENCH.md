# 库存工作台

## 本批已完成

- SKU 增加可配置的 `安全库存`，默认值为 `0`；它是数据库字段，不依赖任何国家、仓库或角色名称的代码判断。
- 有 `sku.update` 动作且在有效组织范围内的人员，可在“商品与 SKU → 商品详情 → SKU 编辑”中维护安全库存。
- 库存工作台显示：库存 SKU 数、在库、可售、已预留、低库存 SKU、缺货 SKU。
- 支持按商品、SKU、条码、站点搜索；按站点、库存状态筛选；按更新时间、可售量、SKU 排序；支持稳定分页。
- 可售库存固定按 `在库数量 - 已预留数量` 计算，绝不通过前端假数据代替；现有负库存拒绝、并发控制、幂等和审计逻辑保持不变。
- API `GET /api/mvp/inventory` 与页面使用同一套库存状态算法，返回 `availableQuantity`、`skuAvailableQuantity` 和 `stockStatus`。

## 库存状态规则

- `OUT_OF_STOCK`：当前可售量小于或等于 0。
- `LOW_STOCK`：当前可售量大于 0，且小于或等于 SKU 安全库存。
- `NORMAL`：其余情况。

一个 SKU 存在多个站点余额时，安全库存状态按当前可见范围内该 SKU 的总可售量计算；站点筛选后则按筛选的站点范围计算，避免把无权限或未选择站点的数据混入判断。

## 权限和范围

- 浏览库存：`inventory.read`。
- 调整库存：`inventory.adjust`，服务端同时验证业务板块、站点和 SKU 归属。
- 设置安全库存：`sku.update`，服务端验证 SKU 所属商品的业务板块；页面仅在有商品读取权限时提供商品详情入口。
- 所有库存调整、订单预留、订单发货扣减继续写入库存事务和审计日志。

## 本批边界

- 本批没有把库存批量导入、收货单、批次/效期、库位或真实仓储系统连接伪装成已完成；这些会作为后续独立、可对账的库存流程建设。
- 安全库存目前是 SKU 级默认值。将来如果实际运营需要“每个站点不同阈值”，会以站点覆盖配置扩展，不会用硬编码例外处理。
