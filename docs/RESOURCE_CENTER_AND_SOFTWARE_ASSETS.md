# 资源中心与软件资产

## 目标

资源中心用于管理设备、软件、云资源、域名、SIM 卡、门禁、钥匙、车辆、办公用品、消耗品、办公场所及其他可配置资源。它是公司级 ERP 的通用模块，不依赖任何固定公司、部门、角色或业务板块名称。

软件资产是资源中心的一个专属视图，不是另一套孤立数据。这样既能统一管理领用、归还、转移、维修和归档，也能保留软件的授权席位、续费与账户标识等业务字段。

## 数据与权限边界

- 每项资源归属 `legal_entity_id`、`business_unit_id`，可选关联 `department_id`、`site_id`、领用 Membership。
- 所有列表、详情、创建、编辑、流转与归档都由服务端按 `Membership + Action + Scope + Access Grant` 判断；前端隐藏按钮不作为安全边界。
- 资源分类、状态、生命周期动作均按业务板块存储，拥有 `resource.configure` 权限的人可新增、编辑、排序、启停，不需要改代码。
- 资源编号、数量、可用数量、状态、版本号和归档状态保存为台账事实；资源不做物理删除，归档后仍保留生命周期和审计证据。
- 软件账号标识的查看与编辑分别需要 `software_asset.account.read` 和 `software_asset.account.manage`。模型不保存密码、Token、API Key 或完整许可证密钥，审计日志也不写入账户标识。

## 当前可用流程

1. 新建资源或软件资产，填写通用资料、数量、所属范围和可选的软件授权资料。
2. 按关键词、分类、状态、部门与页码筛选；服务端稳定排序并返回统一分页元数据。
3. 打开详情，查看领用人、数量、位置、到期日、软件席位、续费资料与受权限限制的生命周期历史。
4. 使用配置化生命周期动作执行分配、借用、归还、解除领用、转移、送修、维修完成、报废、遗失和归档。
5. 管理员在资源配置中维护分类、状态和流转动作。编码是稳定引用，不能直接改写，避免资产历史与审计记录断链。

## 数据完整性与并发

- 数据库约束保证 `quantity >= 1`、`0 <= available_quantity <= quantity`，并限制软件已用席位不超过总席位。
- 每项资产维护 `version`。编辑、流转与归档使用条件更新；若其他人已修改，接口返回 `409 RESOURCE_VERSION_CONFLICT`，不会静默覆盖数量或领用状态。
- 生命周期事件与审计只在资产条件更新成功后写入，避免并发请求重复扣减或重复生成历史。

## 已知后续项

- 维修、保险、租金等成本明细账与借用协议附件尚未进入本批次。
- 到期、低库存目前有统计，尚未形成可配置的待办/通知规则。
- 完整生命周期历史目前详情默认取最近 100 条；若历史量较大，下一批补独立分页查询。
- 资源导入/导出与第三方资产系统对接应采用可配置模板和人工确认，不直接复制旧 ERP 数据。

## 本地验收入口

- 资源中心：`/admin/resources`
- 软件资产：`/admin/software-assets`
- 配置入口：资源中心右上角的“资源配置”

本模块仅使用本地 PostgreSQL 与虚构 Seed 数据；没有连接旧生产库、部署生产、推送代码或接入真实第三方账号。
