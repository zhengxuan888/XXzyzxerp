## 角色体验顺序

| 顺序 | 账号 | 体验重点 |
| --- | --- | --- |
| 1 | `demo_sales` | 手工录入电商客户、填写收件信息、COD 金额、上传客户沟通凭证、提交核单 |
| 2 | `demo_reviewer` | 查看 `DEMO-ORDER-002`，体验审核通过、退回和作废权限 |
| 3 | `demo_shipping` | 查看 `DEMO-ORDER-003`，进入待发货工作台、填写/回填物流信息、上传出货凭证 |
| 4 | `demo_after_sales` | 查看 `DEMO-ORDER-001`，查看客户邮箱/WhatsApp/产品/物流单号，展开轨迹、备注、标签并标记处理 |
| 5 | `demo_finance` | 验证费用和审批菜单仅在授权范围内显示 |
| 6 | `demo_hr` | 验证员工、考勤、请假和公告菜单范围 |

## 虚构演示订单

- `DEMO-ORDER-001` / `DEMO-TRACK-001`：运输中，已有轨迹、售后备注和“已通知客户”标签。
- `DEMO-ORDER-002`：审核中，供核单角色处理。
- `DEMO-ORDER-003`：核单通过、待发货，供发货角色处理。

## 明日验收重点

1. 销售录单页不要求选择历史客户，客户信息直接手工填写。
2. 提交核单前必须上传客户沟通图片/PDF等凭证。
3. 回填物流单号不等于确认发货；必须上传出货凭证并点击确认发货。
4. 普通销售账号看不到无权限的物流动态轨迹和物流单号。
5. 物流售后账号可以查看客户与订单信息，并对每一条轨迹备注、打标签、标记已联系。
6. 跨业务板块和跨部门直链/API访问必须拒绝。
