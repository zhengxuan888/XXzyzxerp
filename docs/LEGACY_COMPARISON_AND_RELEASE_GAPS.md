# 旧 ERP 对照与 V2 发布差距

更新日期：2026-07-29

本报告只做对照和发布门禁，不改变已确认的业务流程。旧 ERP 是业务事实基线；V2 只有在逐项验收通过后才允许替换旧系统。

## 当前结论

- V2 已具备组织隔离、数据库驱动权限、订单主链、附件、库存安全基础、统一收件箱和 Ship24 可插拔适配器。
- V2 不应复制旧 ERP 的角色硬编码、物流回填即发货、前端隐藏代替后端鉴权等缺陷。
- 目前不能宣布可替换：运行态验收、真实物流模板、真实 Ship24 联调、员工 UAT 和部分售后闭环仍未完成或未验证。

## 功能对照

| 业务模块 | 旧 ERP 已确认能力 | V2 当前状态 | 发布判断 |
|---|---|---|---|
| 订单录入 | 手工电商客户、店铺 ID、SKU、收件人、邮箱、WhatsApp、COD、附件、地址辅助 | 主字段、客户手填、COD、附件和提交核单已实现 | 需用员工真实页面逐字段验收 |
| 批量录单 | Excel 解析、逐行错误、批量写入 | 已有配置化模板、预览、事务写入和错误行 | 需用物流/业务实际文件验收 |
| 核单 | 通过、退回并填写原因、作废、审计 | 有状态动作和审批接口 | 需补齐非法状态跳转和实际角色验收 |
| 待发货 | 只显示核单通过且未发货订单 | 页面和接口存在 | 需验证普通录单员工不可读队列 |
| 发货 | 物流单号、出货凭证、确认发货 | 明确分离“回填单号”和“确认发货” | 规则合理，需端到端验证 |
| 物流商模板 | 多承运商导出、回传单号、匹配订单 | 模板和回传接口已存在 | 五份实际模板必须逐字段验收 |
| 物流追踪 | Ship24、筛选、事件备注、标签、未处理、超时提醒 | Ship24 adapter、同步、Webhook、事件模型已存在 | 真实 Key、Webhook、国家规则和调度未验收 |
| 售后跟单 | 按轨迹联系客户、异常待办、处理状态 | 物流事件/跟进基础能力存在 | 高优先级待办和客户通知闭环未证明 |
| 客户 | 手填客户，按联系方式识别历史订单 | 支持手填和历史匹配 | 需验证重复客户归并和历史订单展示 |
| 员工/组织 | 员工、上下级、部门数据范围 | Membership、Scope、Grant 已配置化 | 需做各部门 UAT 和越权矩阵 |
| 财务/人事/行政 | 费用、付款、考勤、请假、审批、文档、公告、报表 | 部分页面/API已存在 | 不能以页面存在代替逐项等价验收 |

## 必须保留的合理设计

1. 客户继续手动录入；电商 COD 不能强制从固定客户下拉选择。
2. 订单总表、核单、待发货、物流追踪/售后保持分工页面。
3. 回填物流单号不改变已发货状态；必须有出货凭证并确认发货。
4. 物流单号、轨迹、轨迹备注和售后动作分开授权。
5. 员工只能看自己或有效上下级范围；跨部门必须由显式 Grant 授权。
6. 角色、菜单、部门、承运商模板和国家规则全部配置化，不写死业务名称。

## P0 发布前差距

- 启动本地 PostgreSQL 和应用，完成登录、录单、附件预览、核单、退回、发货、轨迹、售后闭环。
- 用实际物流商导出模板和回传模板做导出、回填、重复行、空单号、错误行测试。
- 用受控 Ship24 账号完成一次真实同步，并确认官方 Webhook 签名与状态字段。
- 验证国家/地区轨迹提醒、三工作日超时、异常高优先级待办和重复事件幂等。
- 验证普通员工、部门负责人、人事、财务、售后、发货人员的读写和详情直链权限。
- 完成数据库、附件备份恢复演练和员工 UAT 签字。

## P1 优化项

- 补齐旧版智能文本录单的字段解析和人工确认界面。
- 统一所有列表的筛选、稳定排序、分页和导出协议。
- 物流事件增加“待通知、已通知、等待回复、需再跟进、已关闭”等配置化处理状态。
- 客户详情增加历史订单、历史沟通和当前售后任务摘要。
- 将财务、考勤、请假、审批等旧模块逐项加入同一验收矩阵。
