# ERP V2 上线门禁清单

任何 Critical 项未通过都不得上线。勾选人必须记录姓名、日期和证据链接。

## A. 范围与旧系统

- [ ] Critical：旧 ERP 已切换为受控只读，未删除、未清空，已取得加密快照与文件清单。
- [ ] Critical：旧数据默认 `DO_NOT_IMPORT`，仅业务负责人签字的白名单数据进入隔离 staging。
- [ ] Critical：测试账号、密码哈希、Token、Session、缓存、日志和垃圾记录未迁移。
- [ ] 选择性迁移已完成去重、状态、金额、时区、组织归属、负责人确认和新旧 ID 映射。
- [ ] 未完成订单、必要员工/客户/商品等首批对象已逐项对账。
- [ ] 旧系统下线/清理边界尚未获创始人单独书面确认时，保持只读可恢复。

## B. 版本、配置与基础设施

- [ ] Critical：发布提交、镜像摘要和迁移清单固定，Git 工作树干净。
- [ ] Critical：`config:check:staging` 通过，仓库/镜像/日志无真实 Secret。
- [ ] PostgreSQL、Redis、对象存储均为私网最小权限并启用传输加密。
- [ ] 域名、DNS、HTTPS 证书、自动续期、HSTS 和反向代理限制已验证。
- [ ] 数据库连接池、CPU/内存/磁盘、超时、上传大小和速率限制已设定。
- [ ] 健康检查、应用/数据库/Redis/对象存储监控及告警接收人已配置。

## C. 数据、备份与回滚

- [ ] Critical：发布前数据库备份有 SHA-256，隔离恢复演练成功。
- [ ] Critical：附件版本、加密、备份和元数据/对象对账演练成功。
- [ ] RTO/RPO、保留期、备份地域和销毁策略已由创始人批准。
- [ ] 上一不可变应用版本可切回，回滚演练满足目标。
- [ ] 迁移使用 `prisma migrate deploy`，无破坏性手工 SQL 或未知迁移。

## D. 权限与安全

- [ ] Critical：创始人、总经理、销售、核单、发货、售后、财务、行政角色完成 UAT。
- [ ] Critical：随机抽查跨公司/板块/部门读写、详情直链、API、菜单均拒绝。
- [ ] Critical：Access Grant 生效、撤销、到期和无转授权拒绝通过。
- [ ] Critical：服务端不信任前端组织 ID，所有敏感写接口执行 Action + Scope + Membership。
- [ ] 管理员账号启用强密码、最小权限和离职/停用流程；演示账户已删除或停用。
- [ ] 依赖与容器镜像漏洞扫描、Secret 扫描和基础渗透测试无未接受的高危项。
- [ ] 安全响应联系人、日志留存、审计查询和事故升级流程已确认。

## E. 业务与员工 UAT

- [ ] Critical：创建员工→Membership/角色→客户/商品→COD 订单→核单→发货→物流跟单售后→费用/审批→审计闭环通过。
- [ ] 订单模板必填项、邮箱验证策略和中文用户名满足员工确认。
- [ ] 金额精度、库存并发防超卖、回滚、状态机和物流字段端到端通过。
- [ ] 售后从发货后开始跟单，物流轨迹备注、异常和责任人操作负担经员工验收。
- [ ] 分页、稳定排序、筛选、空/错误/加载状态和移动端核心操作通过。
- [ ] 各角色工作台、动态菜单和常用主路由经过实际员工试用。
- [ ] 员工培训、操作说明、反馈渠道和首周支持排班已准备。

## F. 附件与统一收件箱

- [ ] Critical：正式私有对象存储适配器已评审，未使用 `LOCAL_DEMO`。
- [ ] Critical：上传真实 MIME/签名/扩展名/大小校验、随机键、越权、404 隐藏枚举测试通过。
- [ ] Critical：恶意软件扫描采用“先隔离、扫描通过后可读”，失败/超时默认拒绝。
- [ ] 图片失败占位、重试、删除权限、审计和附件备份恢复通过。
- [ ] 真实渠道资料与账号尚未获得批准时，统一收件箱仅保持 Demo Adapter。

## G. 性能、观测与放行

- [ ] 预发布使用目标数据量完成登录、列表、订单写入、库存事务、附件和收件箱性能测试。
- [ ] P95 延迟、错误率、并发用户和数据库连接阈值已由业务/技术负责人确认。
- [ ] 告警演练、磁盘容量、备份失败、证书过期和对象扫描失败均能通知责任人。
- [ ] 上线窗口、冻结时间、最终增量选择性同步、回滚负责人和业务通知已确认。
- [ ] 创始人、业务负责人、技术负责人完成最终签字。
