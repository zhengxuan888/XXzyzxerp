# 旧 ERP 物流追踪功能保留清单

> 2026-07-24 对旧服务器源码的只读盘点。目标是保留真实有用能力，并重做售后操作负担和权限风险，不照搬旧实现。

## 确认存在且需要保留

### 追踪工作台

- 待填物流单号、运输中、派送中、已送达、未处理、总计的快捷统计。
- 搜索订单号、物流单号、收件人。
- 按录单员工、售后负责人、物流状态、异常类型、国家、追踪时效、未处理状态筛选。
- 异常订单分类统计和一键进入对应队列。
- 分页、批量选择、批量结案。
- 订单图片预览和灯箱查看。
- 物流单号手工录入和批量导入。
- 多种物流商 Excel 模板导出。

### 轨迹与异常

- 对接 Ship24 获取轨迹和预计送达日期。
- 手动同步，以及运输中/派送中订单的周期同步。
- 中英文物流状态归一化。
- 轨迹时间线、最新节点、地点、时间。
- 超过 48 小时未更新、超过 3 个工作日未更新、发货后轨迹未上线提醒。
- 投递失败、异常、退回等异常识别。
- 单个轨迹节点标记“已处理 / 未处理”。
- 记录处理时间和处理人。
- 每个轨迹节点填写处理备注，提供快捷处理标签。
- 跳转 Ship24 查看原始轨迹。

### 订单与下游动作

- 签收成交与退回结束。
- 售后负责人和售后状态过滤。
- 物流账单导入与查询。
- 物流详情能查看订单、员工、收件、商品和订单截图。

## V2 不应照搬的实现

- 旧页约 2200 行，查询、规则、导入导出、异常判断和 UI 混在一个组件内，维护成本高。
- 国家与专线路由映射写死在前端，应改为物流渠道/服务区域配置。
- 前端根据 `role === aftersales/post` 自动限定视角不等于后端数据隔离。
- 已抽查的旧 `tracking` 和 `tracking-notes` 路由未看到统一 Membership + Action + Scope 鉴权链路；V2 必须后端强制验证。
- 轨迹备注以整块 JSON 覆盖保存，存在并发覆盖风险；V2 使用独立处理记录并做乐观并发控制。
- 使用数组下标定位轨迹事件不稳定；V2 每个标准化事件使用独立 ID 和来源幂等键。
- 浏览器每 30 分钟触发同步会随打开页面数量重复执行；V2 改为后台任务，页面仅触发有权限的手动刷新。
- 处理动作只做二态标记不能表达负责人、处理结果、下次跟进时间和售后结论。
- 批量结案标注“不可撤销”但应提供权限控制、二次确认、审计和可控纠错流程。

## V2 目标：减少售后工作量

### 正式业务归属

- 快递发出并确认发货后，订单自动进入售后物流工作台。
- 售后负责从发货开始，到签收、退回入库或其他方式结案的完整物流生命周期。
- 正常运输订单也必须持续跟踪并完整显示，不能只显示异常订单。
- 正常订单由系统自动同步和更新状态，不要求售后逐节点执行无意义的“已处理”操作。
- 发生异常、超时或需要联系客户时，系统提升优先级并生成必须处理的售后待办。
- 签收后需要按业务规则继续检查 COD 回款；退回订单必须跟踪到仓库确认收货后才能结案。

所有物流订单进入统一售后工作台，系统自动归类和排序；其中异常订单进入“待处理”队列。

每条异常任务至少包含：

- 订单、物流单、渠道、国家、当前节点和异常类型。
- 优先级、负责人、首次发现时间、最后更新时间、响应时限。
- 处理状态：待处理、处理中、等待客户、等待物流商、已解决、无需处理。
- 处理结果、备注、下次跟进时间、附件。
- 自动建议的下一动作，但最终由员工确认。

系统自动完成：

- 去重同一轨迹事件。
- 新轨迹到达后更新现有异常，而不是重复创建任务。
- 恢复正常或成功签收时自动关闭满足规则的异常。
- 向售后显示全部物流订单，并把需要人工行动的订单单独集中到高优先级队列。
- 常规签收、正常运输默认不要求售后手动点击“已处理”。
- 负责人、国家、渠道、超时规则、快捷处理标签全部配置化。
- 历史导入值 `CK` 已确认代表捷克；标准化为 `CZ`，并保留原始值与转换审计。

## 权限 Action 建议

- `shipment.read`
- `shipment.tracking_number.manage`
- `tracking.read`
- `tracking.sync`
- `tracking.exception.read`
- `tracking.exception.assign`
- `tracking.exception.handle`
- `tracking.note.create`
- `tracking.batch.close`
- `tracking.import`
- `tracking.export`
- `logistics_bill.read`
- `logistics_bill.import`

每个 Action 均与当前 Membership、业务板块和数据 Scope 一起校验。员工是否能看完整轨迹、客户联系方式、金额和他人处理记录分别配置，不能只靠隐藏菜单。

## 验收 Gate

1. 正常订单不会制造售后待办。
2. 同一异常重复同步不会产生重复任务。
3. 新异常自动进入正确负责人队列。
4. 处理、转派、备注、关闭均写审计日志。
5. 撤销权限后页面菜单和 API 同时拒绝。
6. 跨业务板块的物流单、轨迹和异常全部不可读取或修改。
7. 同步失败可重试且不会覆盖已保存的人工处理信息。
8. 轨迹字段从供应商响应到数据库、API、列表和详情端到端不丢失。
9. 售后可在一个队列中完成主要工作，不需要逐条打开所有正常订单。
10. 发货后自动进入售后工作台，正常运输、签收、退回和结案状态均可连续追踪。
