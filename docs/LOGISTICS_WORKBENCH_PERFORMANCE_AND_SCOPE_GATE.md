# 物流工作台：性能与权限范围 Gate

日期：2026-07-31
范围：本地 ERP V2；未连接旧生产库，未部署，未 Push。

## 本次收口

- 物流列表 API 在数据库层合并当前 Membership 的 `Action + Scope` 查询条件，再执行稳定分页；不再先取全量物流记录并逐条重复鉴权。
- 物流工作台仍保留现有卡片、筛选、快捷标签、逐轨迹备注和分页交互；列表候选集只取轻量字段，客户、商品、轨迹、备注详情只加载当前页。
- `SELF` 与 `SUBORDINATES` 的订单/物流归属改用 `ownedByMembershipId`，不再只根据共享的 `creatorUserId` 判断，避免同一员工在多个岗位或部门间串数据。
- 物流详情、轨迹、同步、跟进、批量备注、回传运单号、待发货页、核单与订单动作均把订单的 Membership 归属带入后端鉴权。
- Access Grant 只在当前有效 Membership 的业务板块生效；角色/菜单的未知条件默认拒绝，不会因尚未实现解释器而放行。
- 迁移补偿了本地历史漂移：恢复店铺筛选索引和物流规则默认值，并添加订单归属、轨迹时间线索引。没有删除或重建本地数据。

## 已知后续项

- 工作台的自定义卡片目前可编辑名称、排序、显隐和匹配规则；“新增任意新卡片类型”仍需独立的数据模型，不应通过写死 key 扩展。
- 多家物流商导出/回传需要补 `模板版本 + 导出批次 + 回传预检/确认 + xls/xlt 兼容`，以保留旧 ERP 的日常物流商表格闭环。
- 物流回款、COD 账单和对账应归入财务板块，独立建模，不混入物流追踪页。
- Ship24/飞书仍只保留受控接口与本地演示能力；真实密钥、真实账号和生产启用需要创始人单独提供并确认。
