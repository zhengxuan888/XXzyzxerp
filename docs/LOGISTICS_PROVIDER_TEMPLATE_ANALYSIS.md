## 3. 标准字段映射模型

V2 内部使用稳定标准字段，模板只保存映射：

| 标准字段组 | 建议内部字段 |
|---|---|
| 订单标识 | `order_no`、`forward_source_no`、`external_reference_no` |
| 物流 | `provider_id`、`route_id`、`shipping_mode`、`fulfillment_type` |
| 收件人 | `recipient_name`、`phone`、`email` |
| 地址 | `country_code`、`country_name`、`state`、`district`、`city`、`street`、`street_no`、`door_no`、`full_address`、`postal_code` |
| 商品 | `customs_name_local`、`customs_name_en`、`product_snapshot`、`sku`、`quantity`、`picking_info`、`customs_code` |
| 申报 | `declared_amount`、`declared_currency`、`cargo_type` |
| COD | `cod_amount`、`cod_currency` |
| 包裹 | `weight`、`package_count` |
| 备注 | `label_note`、`picking_note`、`internal_note` |
| 审计 | `export_batch_id`、`template_version_id`、`exported_by_membership_id` |

模板配置至少包含：

- 工作表名称、表头行、数据起始行；
- 输出列位置和表头原文；
- 标准字段或固定值来源；
- 国家/线路/代发或转寄的适用条件；
- 文本、金额、整数、重量、日期等格式；
- 空值处理、必填校验、最大长度；
- 组合格式化规则，例如 `SKU:数量;`；
- 模板原文件 SHA-256 和生效/失效时间。

## 4. 数据质量与导出风险

### Critical

1. **电话和邮编被 Excel 自动当成数字**：可能丢失前导零或变成科学计数法。导出时必须强制文本格式。
2. **订单号和 SKU 必须是文本**：不能自动转换数字、日期或科学计数。
3. **无表头尾列含真实数据**：在物流负责人确认前禁止默认发送，避免泄露员工信息或产生物流商误读。
4. **申报金额与 COD 金额不可混用**：模板同时存在两套金额和币种。
5. **转寄有两个订单标识**：必须明确原单/转寄号与内部订单号的关系。

### High

1. 西葡模板使用中文国家名，其他模板多用 ISO 二字码，需要模板级转换。
2. 东欧地址需要拆分州省、区、城市、街道、门牌号；西葡可使用完整地址，不能共用一套简单拼接。
3. 邮箱样例可能含首尾空格或换行，导出前需清理但保留原始订单值用于审计。
4. 电话、门牌号、邮编在不同文件中存在数字/文本混合。
5. 原模板含客户个人信息；模板存储、下载和导出批次必须受权限控制并设保留期。

## 5. 导出 Gate

1. 只有核单通过且属于当前业务板块的订单可进入导出批次。
2. 系统按物流商、模板版本、代发/转寄、国家和线路分组，禁止混用模板。
3. 导出前展示字段预览和逐行错误；任一必填字段缺失时阻止该行。
4. 电话、邮编、订单号、SKU、门牌号全部按文本输出。
5. 金额使用 Decimal 事实值和明确币种，不使用 JavaScript 浮点重新计算。
6. 导出文件保存模板版本、批次、订单清单、操作者、时间和 SHA-256。
7. 防止 Excel 公式注入：以 `= + - @` 开头的外部文本必须安全转义。
8. 不在导出表中加入未配置字段；无表头列需单独确认后才能启用。
