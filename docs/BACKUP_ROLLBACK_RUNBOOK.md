# ERP V2 备份与回滚运行手册

## 1. 待创始人确认的恢复目标

| 项目 | 建议起点 | 最终确认 |
|---|---:|---|
| 数据库 RPO | ≤ 15 分钟 | 待确认 |
| 数据库 RTO | ≤ 2 小时 | 待确认 |
| 附件 RPO | ≤ 1 小时 | 待确认 |
| 附件 RTO | ≤ 4 小时 | 待确认 |
| 旧 ERP 只读保留期 | 至少完成 V2 验收和书面确认后 | 待确认 |

## 2. 数据库备份

发布前由受控主机执行自定义格式备份，命令中的连接信息必须来自环境变量或 Secret Manager：

```powershell
pg_dump --format=custom --no-owner --no-acl --file erp_v2_YYYYMMDD_HHMM.dump $env:DATABASE_URL
Get-FileHash erp_v2_YYYYMMDD_HHMM.dump -Algorithm SHA256
```

同时记录数据库版本、迁移状态、Git 提交哈希、文件大小和 SHA-256。备份必须加密、最小权限存放，并按保留策略自动过期。

## 3. 恢复演练

恢复只能进入隔离的空白演练数据库：

```powershell
createdb erp_v2_restore_drill
pg_restore --exit-on-error --no-owner --no-acl --dbname erp_v2_restore_drill erp_v2_YYYYMMDD_HHMM.dump
```

演练验收：

1. SHA-256 与备份登记一致。
2. `prisma migrate status` 无缺失/未知迁移。
3. 核心表行数、关键外键、订单金额汇总和附件记录数对账。
4. 使用演练账号验证登录、权限隔离和关键只读页面。
5. 记录恢复开始/结束时间，确认是否满足 RTO。
6. 演练库按审批安全销毁，日志保留但不包含业务明文。

只有“备份成功”没有恢复演练，不算通过上线门禁。

## 4. 附件备份

- 当前 `LOCAL_DEMO` 仅限本地，不作为预发布/生产方案。
- 正式私有对象存储需启用版本控制、服务端加密、生命周期、跨区域/跨账号备份（按业务确认）和恶意软件扫描。
- 每次发布记录附件元数据数量、对象数量、总字节数和清单摘要；抽样验证数据库 `storageKey` 对象存在且校验和一致。
- 恢复顺序：先恢复数据库到隔离环境，再恢复对象版本，最后运行“元数据存在但对象缺失 / 孤儿对象”对账。
- 删除操作需保留软删除/对象版本恢复窗口，禁止应用回滚时批量物理删除附件。

## 5. 应用版本回滚

1. 停止继续放量并冻结高风险写操作。
2. 记录故障时间、版本、请求 ID 和影响范围。
3. 若数据库迁移向前兼容，流量切回上一不可变应用版本。
4. 验证健康、登录、权限、订单读取和审计。
5. 数据库优先采用前向修复；不得自动执行破坏性 down migration。
6. 只有当向前修复不可行且业务书面批准时，才从已验证备份恢复到新数据库并切换。
7. 对 RPO 窗口内的写入建立人工对账清单，不能静默丢弃。

## 6. 回滚触发条件

- 登录或 Session 大面积失败；
- 跨业务板块/跨部门越权；
- 金额、库存或订单状态事实错误；
- 迁移失败、核心表约束异常；
- 附件泄露或对象不可用；
- 关键接口错误率/延迟超过已批准阈值；
- 审计日志无法记录高风险写操作。

每次演练都应留下：操作人、审批人、版本、备份校验和、实际 RPO/RTO、失败点和改进项。
# 本地自动恢复演练

本地 Docker 环境必须使用可重复脚本验证“备份可恢复”，不能只验证 `pg_dump` 成功：

```powershell
pnpm run backup:drill
```

脚本会创建唯一隔离数据库，验证备份 SHA-256、全部 public 表行数、Prisma 迁移以及 Local Demo 附件的存在性、字节数和 SHA-256，然后清理演练资源。最近一次证据见 `docs/LOCAL_BACKUP_RESTORE_DRILL_REPORT.md`。

该命令仅适用于本地 Docker 演练。生产备份仍必须使用独立凭据、加密存储、异地副本和审批流程。
