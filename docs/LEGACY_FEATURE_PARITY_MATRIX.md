# 旧 ERP 功能保留与优化对照矩阵

更新时间：2026-07-26

## 使用规则

旧 ERP 是当前业务事实基线。V2 只允许在保留原功能的前提下增加优化；业务流程、字段含义和员工操作方式发生变化前必须得到业务负责人确认。本文件区分“已核对事实”“V2 已有能力”和“待补齐/待确认”，不把计划当成已完成。

## 订单—核单—发货—物流—售后主链

| 旧 ERP 功能事实 | 旧 ERP 证据 | V2 当前对应 | 状态/处理原则 |
|---|---|---|---|
| 手动录入订单 | `src/app/(dashboard)/order-entry/page.tsx`：订单弹窗与字段表单 | `/admin/orders`、`OrderEntryForm` | 保留手动录入；不得强制选择固定客户 |
| 店铺 ID、物流渠道、订单日期 | 旧录单表单字段 | 订单模板、物流渠道、订单日期 | 保留；模板只提供默认值，不得隐藏手动输入 |
| 商品名称可手动输入并可搜索 SKU | 旧录单 `product_name` 与库存搜索 | 商品/SKU选择和商品名称字段 | 保留两种方式；不能只剩下拉选择 |
| 收件人、电话、国家、地区、城市、地址、邮编 | 旧录单收件信息区 | 订单收件字段 | 保留；必填项由订单模板配置 |
| 客户邮箱格式/真实性检测 | 旧录单调用 `/api/validate-email` | V2 邮箱验证接口和模板校验 | 保留；检测结果不能伪造为已验证 |
| 客户 WhatsApp、员工 WhatsApp | 旧录单支付与联系方式区 | 订单字段 | 保留；权限控制字段显示，不删除字段 |
| COD 金额、币种、付款方式、运费 | 旧录单支付区 | Decimal/最小货币单位策略 | 保留；禁止浮点作为资金事实 |
| 订单截图上传、预览、删除 | 旧录单图片上传与预览 | 安全附件模块、订单沟通凭证 | 保留；提交核单前的凭证规则按已确认流程执行 |
| Excel 批量导入订单 | 旧录单 `handleFileUpload`、`/api/orders/batch` | V2 尚需完整模板导入适配 | 待补齐；模板必须配置化，不能写死物流商 |
| 智能文本录单 | 旧录单 `handleSmartImport` | V2 尚未等价实现 | 待补齐；只能作为手动录入辅助，不能绕过校验 |
| 订单列表按日期、订单号、收件人搜索 | 旧录单列表筛选 | V2 订单列表分页/搜索 | 保留并统一分页协议 |
| 订单记录按订单状态、物流状态、日期筛选 | `order-records/page.tsx` | V2 订单总表与状态筛选 | 保留；核单、物流追踪仍为独立页面 |
| 核单通过 | `fulfillment-review/page.tsx`、`/api/orders/[id]/review` | V2 核单工作台 | 保留；通过后才进入待发货 |
| 核单退回并填写原因 | 旧核单退回弹窗 | V2 审核动作 | 保留多种退回原因；具体原因配置化 |
| 核单查看客户邮箱、WhatsApp、订单截图 | 旧核单详情抽屉 | V2 订单详情/凭证面板 | 保留；字段可按权限显示 |
| 已通过订单导出给物流商 | `/api/orders/export-confirmed`、物流追踪导出菜单 | V2 物流商模板配置 | 保留；物流商与字段映射不能写死 |
| 物流商回传表格自动匹配订单并回填单号 | 旧物流追踪 `handleImportTracking` | V2 回传导入/匹配 | 保留；回填运单号不等于确认发货 |
| 手动填写物流单号 | 旧物流追踪单号弹窗 | V2 发货工作台 | 保留；仍须出货凭证和“确认发货” |
| 物流同步与状态翻译 | `/api/tracking/sync`、物流追踪页面 | V2 物流事件模型/Ship24预留 | 保留；国家规则配置驱动 |
| 每条物流轨迹备注 | 旧 `tracking-notes` | `LogisticsEventAnnotation` | 已增强：独立备注、标签、处理状态和审计 |
| 每条物流轨迹标记已处理 | 旧 tracking event `handled` | `LogisticsEventAnnotation.isHandled` | 已增强：独立持久化，避免覆盖物流事实 |
| 国家、状态、轨迹更新时间、异常、未处理、物流未上线筛选 | 旧物流追踪筛选区 | V2 物流工作台 | 已有基础筛选；待继续逐项核对字段显示 |
| 售后查看物流并跟进客户 | 旧 aftersales/物流追踪页面 | V2 物流售后工作台 | 保留；正常轨迹和异常轨迹均可记录跟进 |
| 物流异常生成待办/提醒 | 员工反馈及旧页面能力 | V2 规则/待办 | 待按已确认国家规则逐项验收 |

## 旧 ERP 其他已发现模块

旧 ERP 目前约有 60 个业务页面和 135 个 API 路由，至少覆盖：客户、员工、人事、权限、审批、考勤、请假、加班、库存、商品/Listing、财务费用、付款、发票、物流账单、COD 回款、对账、文档、公告、任务、工作日志、统计报表、流量、公司资产、软件资产和回收站。

本矩阵本轮先收口订单主链；其他模块只记录存在事实，不把 V2 未完成模块标记为已完成。

## 当前明确的优化边界

1. 保留旧 ERP 的手动录单和截图/沟通凭证，不改成固定客户选择流程。
2. 历史客户只能用于查询、提示和可选关联，不能阻塞新客电商订单。
3. 物流回填单号、上传出货凭证、确认发货必须是可区分的三个动作。
4. 旧 ERP 有的筛选、导入、导出、备注和批量操作，不得因 UI 重做而消失。
5. 新增的自动匹配、提醒、异常待办和智能建议必须可关闭、可授权、可审计。
