## 订单生命周期路由

| 环节 | 旧页面 / API | V2 处理原则 |
| --- | --- | --- |
| 录入 | `order-entry`、`POST /api/orders` | 保留 SKU 搜索/手填、模板默认值、地址、COD、附件；后端字段白名单与组织归属校验 |
| 记录查询 | `order-records`、`GET /api/orders` | 统一分页、稳定排序、搜索筛选与权限 Scope |
| 员工订单 | `employee/orders`、`employee-orders` | 用 Membership + Scope 代替角色名或部门名硬编码 |
| 经理审核 | `manager/orders`、`orders/[id]/review` | 显式订单状态机、Action 权限、审计日志 |
| 履约审核 | `fulfillment-review`、`fulfillment-orders` | 审核与发货动作分离，禁止前端直接改状态 |
| 待发货 / 发货 | `orders/pending-ship`、`orders/[id]/ship` | 发货时校验 SKU 库存、组织归属和物流必填字段 |
| 物流追踪 | `logistics-tracking`、`orders/[id]/tracking` | 轨迹追加、异常处理、售后备注分别授权，字段端到端不丢失 |
| 轨迹同步 | `tracking/sync` | 后台任务幂等、失败可重试、来源与同步时间可追溯 |
| 物流账单 | `logistics-bills`、`logistics-bills/import` | 与订单/物流单关联，金额使用最小货币单位，导入先预检 |
| 批量关闭 | `orders/batch-close` | 独立 Action、范围校验、确认与审计 |
| 导出 | `orders/export-confirmed` | 独立导出权限、字段脱敏、业务板块过滤 |
| 删除 / 回收站 | `orders/[id]`、`recycle-bin/orders` | 默认软删除；恢复、永久删除分别授权并记录审计 |

## 旧录入页确认存在的能力

- 品名关键词搜索 SKU，同时允许手动填写品名。
- 智能地址识别，提取国家代码、邮编、区/市和详细地址。
- Excel 批量导入及字段别名兼容。
- 图片拖放、压缩、并行上传，旧页面上限为 20 张。
- 客户邮箱验证。
- 订单号自动生成。
- 物流渠道、申报金额/币种、数量、重量、订单日期。
- 收件人、电话、国家代码、邮编、区、市、详细地址。
- COD 金额/币种、到付/预付、客户与员工 WhatsApp、邮箱、备注。
- 列表搜索、日期筛选、分页、图片预览和按动作区分的删除/导入权限。

## V2 功能保留 Gate

1. 不能只还原表单外观；上述路由动作必须进入权限矩阵。
2. 所有订单、发货、轨迹、账单查询必须由当前 Membership 派生业务板块范围。
3. 模板只配置默认值、显示规则和必填规则；订单保存模板快照。
4. SKU 搜索可手填，但提交时 SKU 与商品、库存、业务板块必须一致，禁止静默匹配错误。
5. 地址识别结果必须由用户确认；国家/地区映射放入可配置主数据，不能散落在页面代码。
6. 图片使用独立附件记录与存储策略，不再固定为 `image_1 ... image_8`。
7. Excel 导入采用预检 → 错误清单 → 确认导入，不直接写入脏数据。
8. 订单状态变更、审核、发货、异常处理、批量关闭、删除和恢复必须写审计日志。
