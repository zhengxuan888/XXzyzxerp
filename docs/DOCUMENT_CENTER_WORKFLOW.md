# 文档中心工作流与安全边界

## 目标

文档中心用于管理公司内部资料、制度、培训材料、合同和业务操作资料。它不是公共网盘：每个文件都归属到当前公司的业务板块与部门，并在服务端按 Membership、Action、Scope 和有效协作授权计算访问范围。

## 使用流程

1. 有 `document.create` 的员工上传图片、PDF、DOCX 或 MP4，并选择可选分类。
2. 新上传资料默认为“待审核”；上传人可在列表中看到自己的资料。
3. 有 `document.review` 且同时具备该资料 `document.read` 范围的人，可通过或退回并留下审核备注。
4. 审核通过的资料，才会按各自的 `document.read` Scope 对其他有权员工显示和提供预览。
5. 有 `document.archive` 且范围匹配的人可归档；归档后不再在正常列表、内容或预览接口中暴露。

页面支持搜索、审核状态、分类、分页和每页条数；手机端以资料卡片显示操作，桌面端使用表格。上传框支持点击选择、拖拽，以及从微信等应用直接粘贴截图。图片和 PDF 可页内预览；DOCX 只做本地纯文本预览，原始排版请下载查看；MP4 提供受控下载，不进行网页内自动播放。

## 权限与数据边界

| 动作 | 用途 | 额外规则 |
|---|---|---|
| `document.read` | 列表、内容、预览 | 所有读操作均以此 Scope 为基础 |
| `document.create` | 上传内部资料 | 新资料从当前 Membership 推导组织归属 |
| `document.review` | 通过/退回待审核资料 | 同时必须拥有该资料的 `document.read` |
| `document.archive` | 软归档资料 | 同时必须拥有该资料的 `document.read` |
| `document.category.configure` | 管理本业务板块分类 | 仅接受 `BUSINESS_UNIT` 或 `ALL` Scope |

前端按钮仅用于体验；每个 API 都在服务端重新校验。列表 API 为每条资料返回由服务端计算的 `canReview` 和 `canArchive`，避免把“当前用户可操作自己”错误地显示在下属或其他部门资料上。

`Document.targetType` 与 `Document.targetId` 目前只保留为业务追溯元数据，不参与授权判断。后续若把文档绑定订单、客户或其他对象，必须先在服务端解析该对象并校验其真实组织归属，绝不能信任前端提交的目标字段。

## 文件安全

- 仅允许 PNG、JPEG、WebP、PDF、DOCX 和 MP4；真实文件签名、声明 MIME、扩展名和大小必须一致。
- 图片最大 5MB；PDF/DOCX 最大 10MB；MP4 最大 50MB。请求在读取文件内容前先检查大小。
- DOCX 在不解压内容的情况下验证 OOXML 中央目录；拒绝 ZIP64、超过 1,024 个条目、超过 50MB 解压量或压缩比超过 100:1 的包。
- 文件使用随机 UUID 存储键，禁止路径穿越和用户自填存储路径。
- 文件关联业务板块、部门、上传人和 Membership。专属文档内容/预览接口还校验附件与文档的业务板块、部门、`targetType=DOCUMENT`、`targetId=document.id` 一致。
- 读取与预览写入只含 MIME、大小、预览类型等元数据的审计记录，不把文件正文、图片内容或审核备注复制进审计日志。
- 本地环境使用 `LOCAL_DEMO` 适配器；生产必须替换为私有对象存储、恶意软件扫描、加密、生命周期与可恢复备份。

## 旧资料与回滚

已有文档数据会保留；迁移后未明确审核状态的历史记录默认按迁移设计保留为可追溯资料。归档是软归档，不删除对象文件。物理清理只能由后续受审计的保留策略任务执行，并且要先完成备份与恢复演练。

本批迁移：`20260731020000_document_center_secure_workflow`。它只应用于 V2 本地/测试数据库，不连接、不导出、不修改旧 ERP 或生产数据库。

## 验收门禁

- 员工能在同一上传框完成选文件、拖拽或粘贴截图，并看到明确失败原因。
- 审核者只能审核自己可读取范围内的待审核资料；归档和预览同样按范围拒绝。
- 无法通过附件 UUID 跨部门读取、删除或替换文件。
- 伪造 MIME、超限文件、普通 ZIP 冒充 DOCX 和异常压缩 DOCX 均被拒绝。
- 审核、归档、内容读取与预览均有服务端审计；移动端无需横向滚动即可完成核心操作。
