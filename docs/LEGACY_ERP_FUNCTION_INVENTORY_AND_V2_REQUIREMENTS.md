# 旧 ERP 全功能盘点与 V2 保留/重做清单

盘点日期：2026-07-24

证据：旧服务器 `/home/ubuntu/zyzxerp` 的只读源码、页面/API/Schema、用户提供的实际页面截图。

旧版本：`main@06bf093`。盘点期间未修改旧服务器、未读取 Secret、未导出业务明文。

## 1. 结论

旧 ERP 不能作为 V2 架构直接复制，但它是必须保留业务能力的重要证据。

- **功能要保留**：员工已经使用或业务闭环依赖的入口、字段、表格、状态和操作。
- **实现要重做**：组织隔离、动态权限、状态机、附件安全、Excel 导入、Ship24 同步、审计和并发控制。
- **不能盲目迁移**：旧账号、密码、Session、Token、公开上传文件、权限缓存、测试/垃圾数据和不明确状态。
- **不能假装已完成**：V2 目前只有部分基础闭环；下表列出的差距必须按 Gate 验收。

## 2. 旧系统功能总览

| 员工管理、批量操作、导出 | 是 | 组织范围、字段白名单、批量任务审计 |
| 部门、上下级、员工选项 | 是 | Legal Entity / Business Unit / Department / Membership |
| 员工证书、文档、考试、技能、培训、奖惩 | 是，分批 | 独立员工档案子模块，不塞进员工主表 |
| 考勤、请假、加班、节假日 | 是 | 按 Membership/站点隔离，审批配置化 |

### 2.3 核单

| 旧功能 | 必须保留 | V2 处理 |
|---|---|---|
| 全部、待核单、审核中、复购、重单队列 | 是，P0 | 状态机和风险标签独立建模 |
| 搜索订单号、收件人、商品 | 是 | 数据范围过滤后搜索 |
| 核对员工、客户、商品、金额、截图、日期 | 是 | 图片/PDF 在线预览 |
| 核单通过 | 是 | 仅允许待核单/审核中进入通过 |
| 退回修改并填写原因 | 是 | 原员工待办、修改后重新提交、全程审计 |
| 直接作废 | 用户确认新增 | 独立权限、必填原因、可配置原因码 |

### 2.4 物流商表格交换与发货

正确闭环以用户最新确认为准：

`核单通过 → 待导出 → 按物流商模板批量导出 → 已发物流商 → 等待回传 → 上传回传表 → 校验/匹配 → 写入物流单号 → 上传发货凭证 → 确认发货 → Ship24 追踪`

| 功能 | 必须保留 | V2 处理 |
|---|---|---|
| 只有核单通过订单进入物流处理 | 是，强制 | 页面和 API 双重校验 |
| 按物流商模板导出 Excel | 是，P0 | Provider + TemplateVersion + FieldMapping 配置化 |
| 物流商回传表导入物流单号 | 是，P0 | 导入批次、预览、错误清单、人工确认 |
| 原单号/客户订单号匹配 | 是 | 可配置匹配键，禁止跨业务板块匹配 |
| 重复单号、空单号、未知订单校验 | 是 | 任一异常不得静默跳过 |
| 回传原文件保存 | 是 | 私有附件、校验和、操作者、批次审计 |
| 待发货列表 | 是 | 仅核单通过且未作废的订单 |
| 发货凭证图片/PDF/视频 | 是 | 图片/PDF 已有安全基础；视频需单独安全 Gate |
| 不发货/作废原因 | 是 | 独立状态与权限，不能伪装成删除 |
| 修改物流单号 | 是但高风险 | 专门 Action、原因、前后值、审计 |
| 确认发货 | 是 | 有效物流单号、凭证、包裹信息齐全后才允许 |

模板引擎必须支持新增物流商而不发版：物流商、模板方向、版本、工作表、表头行、列映射、固定值、格式化、适用国家/渠道/仓库、必填规则、匹配键、启停时间。

| 旧功能 | 必须保留 | V2 处理 |
|---|---|---|
| Ship24 手动/周期同步 | 是 | Provider Adapter + 后台任务 + 重试/游标 |
| Ship24 Webhook | 是 | 验签、幂等、重放防护、失败队列 |
| 自动识别承运商/状态/预计送达 | 是 | 保存原始值和标准化值 |
| 轨迹时间线、地点、时间、原文 | 是 | 每个事件独立 ID，不用数组下标 |
| 中英西等状态翻译 | 是 | 词典/规则配置化，保留原文 |
| 订单号、物流号、收件人搜索 | 是 | 稳定分页与范围过滤 |
| 员工、状态、异常、目的地、线路、时效筛选 | 是 | 查询参数白名单与数据库索引 |
| 待填单号、运输中、派送、送达、未处理统计 | 是 | 统计口径配置化且可解释 |
| 48 小时无轨迹、超过时限未更新 | 是 | SLA 规则按渠道/国家配置 |
| 派送失败、地址错误、拒收、退回等异常 | 是 | 异常规则生成高优先级任务 |
| 每个轨迹节点的处理状态、标签、备注 | 是，P0 | 独立 ContactTask/FollowUp，不覆盖轨迹事实 |
| 处理人和处理时间 | 是 | Membership 归属和 Audit Log |
| 批量签收成交/退回结束 | 是 | 权限、确认、可纠错流程、审计 |
| 跳转 Ship24 原始轨迹 | 是 | 仅授权用户可见 |
| 物流账单/回款 | 是 | 与订单、物流单、币种、批次对账 |

用户确认的客户联系规则：

1. 电子信息建立、标签创建、等待揽收等“初始轨迹”可配置为 `无需通知`。
2. 快递实际揽收/首次实体扫描后，每条新轨迹生成独立客户通知待办。
3. 初始轨迹停留超时，生成 `待联系物流商`，不一定通知客户。
4. `准备派送`、`派送中`、`到达代取点`立即生成高优先级客户通知待办。售后必须提醒客户在家或安排代收、保持电话畅通；COD 订单还需提醒客户准备付款。
5. 地址错误、联系不上收件人、派送失败、拒收、包裹滞留、开始退回等无论阶段均生成紧急待办，并按需同时联系客户和物流商。
6. 每个节点显示 `无需通知 / 待通知 / 已通知 / 等待回复 / 需再跟进 / 已关闭`。
7. 已通知必须记录渠道、时间、员工、客户回复、结果、备注和下次跟进时间。
8. 同一 Ship24 事件重复同步不得重复生成待办。

## 3. 旧实现中不能照搬的问题

### Critical

1. **组织字段缺失**：旧核心订单表没有 Legal Entity / Business Unit / Department，无法可靠隔离。
2. **角色名硬编码**：多个 API 判断 `admin/ceo/manager/aftersales/fulfillment`；改名或新增角色会失效。
3. **菜单权限不等于动作权限**：旧权限以 `menu_key + role` 为主，不能证明详情/API/字段级安全。
4. **发货接口校验不足**：旧接口允许“物流单号或发货证明有一个即可”，与当前确认规则冲突。
5. **附件公开**：上传写入 `public/uploads`；只看 MIME/扩展名，无文件签名、资源归属和读取鉴权。
6. **轨迹 JSON 覆盖**：轨迹及处理信息嵌在订单 JSON；并发备注/同步容易覆盖。
7. **Excel 直接逐行写入**：旧回传导入在前端循环更新，没有 staging、整批校验和原始文件证据。

### High

1. `orders` 页面接近 3000 行，订单、发货、物流、图片、导出和权限混合。
2. `logistics-tracking` 页面超过 2200 行，国家/线路/模板/状态翻译硬编码在前端。
3. 旧订单 Schema 只提供 `image_1..image_8`，页面又允许 20 张，数据模型不一致。
4. 旧上传文件名使用 `type + Date.now()`，不具备强随机和内容校验。
5. 状态字段散落，核单、订单、发货、物流、售后之间缺少统一状态机。
6. 页面隐藏员工/经理物流字段，不等于后端字段级授权。
7. 批量结束被描述为不可逆，缺少受控纠错和复核流程。

## 4. V2 当前差距与实施顺序

### P0：必须先完成

1. 订单沟通凭证：图片/PDF，至少 1 个、最多 20 个，提交核单硬 Gate。
2. 核单工作台：队列、退回原因、作废、复购/重单风险、附件预览。
3. 物流商配置与 Excel 模板版本/映射。
4. 导出批次、回传文件、staging 校验、物流单号确认导入。
5. 发货凭证、正确物流单号和确认发货 Gate。
6. Ship24 Adapter、Webhook/轮询幂等、重试和状态标准化。
7. 每轨迹客户通知任务、初始免通知规则、异常/SLA、负责人和审计。
8. 订单→核单→物流商→发货→追踪→售后的端到端权限与状态机测试。

### P1：业务运营完整

1. 客户重复识别与跟进。
2. 物流账单、COD 回款导入和对账。
3. 售后目标/日报、经理视图。
4. SKU/库存/上品完整操作。
5. 任务、通知、工作日志和角色工作台。

### P2：公司级完善

人事档案、培训奖惩、考勤请假加班、财务全套、资产文档、投流运营、统计月报等，均通过公司/业务板块/部门配置启用。

## 5. 验收 Gate

1. 未上传客户沟通图片/PDF不能提交核单。
2. 核单未通过或已作废订单不能进入物流商导出/发货。
3. 模板新增、改列、停用不修改代码即可完成。
4. 回传表任何空值、重复、未知订单、跨板块订单均进入错误清单，不静默写入。
5. 未上传发货凭证或未确认物流单号不能确认发货。
6. 确认发货后自动建立 Ship24 追踪；重复回调不重复轨迹/任务。
7. 初始免通知规则可配置；首次实体扫描后每条新轨迹产生客户联系任务；准备派送和派送中必须立即进入高优先级通知队列。
8. 每个客户联系任务可证明谁、何时、通过什么渠道、联系结果及下一步。
9. 轨迹同步不能覆盖人工备注；跨公司/板块/部门读取写入全部拒绝。
10. 作废、退回、通过、导出、导入、改单号、发货、通知、结案全部写审计。
